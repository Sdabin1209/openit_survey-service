# ADR-0041: 노출 선언 라벨 io.openit.exposure (U47)

## 상태
승인(헤드 브리프 U47(1), 계약 boundary-contracts `Exposure`, 이미지 라벨 `io.openit.exposure`, 구조 규칙 1).

## 맥락
deploy `config/Caddyfile`이 이 영역의 API 경로·메서드·역할을 직접 안다(규칙 1 위반). 영역이 노출 표를 이미지 라벨로 선언하면 deploy가 Caddyfile을 그 선언으로 만들거나 대조할 수 있다(deploy 몫은 나중).

## 결정
리포 안 `deploy-exposure.json`이 노출 표의 정본이다. `scripts/build-image.sh`가 이 파일을 한 줄 JSON으로 `--label io.openit.exposure=...`로 이미지에 달고 `BuildImageResult.labels`에 나온다. 표는 코드의 실제 라우트를 옮긴 것이다:
- 게이트웨이 밖으로 내는 것: `/healthz`·`/readyz`(none), 키오스크 세션 API(`device-token`: `POST /v1/sessions`, `.../turns`, `.../end`, `.../staff-call/retry|report`, `GET .../state`), 직원 경로(`account`, 역할 `staff`, 상류 토큰 이름 `survey-api-staff`, `X-Openit-User` 설정, 스트리밍: `/v1/staff/*` 와 `/v1/sessions/*/intervention`), 
- 내지 않는 것(`denied`): `/v1/sessions/*/risk-signals`, `/v1/results`, `/v1/results/*`. 서비스는 이 경로를 자기 토큰(risk-source, result-reader)으로 내지만 게이트웨이 밖으로는 내지 않는다.
시험(`tests/test_exposure.py`)이 표가 계약 `Exposure`를 통과하는지, 코드의 모든 라우트(소스에서 읽은 `/v1` 경로 리터럴과 정규식 포함)가 표에 있는지, `denied`가 모든 메서드에서 막히는지, 라벨 값이 파일과 같은지(실제 빌드 한 번)를 본다.

## 왜
계약 `Exposure`와 라벨 키가 정의돼 있다. 코드가 정본이라는 브리프를 따라 표를 코드 라우트에서 만들고 Caddyfile의 survey-service 블록은 읽기만 했다(고치지 않았다).

## 코드와 Caddyfile이 어긋나는 곳 (코드가 정본)
1. Caddyfile은 키오스크용으로 `/v1/sessions`와 `/v1/sessions/*`(모든 메서드)를 서비스에 넘긴다. 서비스가 아는 것은 위 6개뿐이라 표는 더 좁다. 그 밖은 서비스가 404를 준다.
2. Caddyfile은 `/v1/staff/*`를 메서드와 상관없이 넘기고 모든 직원 경로에 `flush_interval -1`·`read_timeout 1h`를 건다. 표는 아는 경로·메서드만 적고 같은 값을 모든 직원 route에 `streaming: true`·`read: 3600000`으로 옮겼다(SSE 경로만 필요하지만 현재 deploy 동작을 그대로 옮겼다).
3. `/healthz`는 게이트웨이가 상류와 무관하게 직접 200을 준다. 표는 서비스가 `/healthz`를 낸다는 사실을 `none`으로 적는다(deploy가 어떻게 쓸지는 deploy 결정).
4. 역할 이름 `staff`는 Caddyfile의 `@role_staff` 이름에서 옮겼다. 계정과 역할의 매핑은 deploy의 설정이라 이 영역이 알지 못한다.
5. 2.x 호환 기기 토큰 경로(Caddyfile의 `@device_ok`)와 기기 인증서 경로(`@device_cert`)는 둘 다 `device-token` 한 종류로 적었다(Exposure에 인증서 종류가 없다). 정확한 구분은 계약의 선언 형식 밖이다.

## 검토한 대안과 버리는 이유
표를 Caddyfile에서 그대로 복사: 코드와 어긋난다(위 1·2). 표를 코드에서 자동 생성: 정규식 라우트라 역할·타임아웃 같은 배포 정보는 코드에 없다. 파일 정본 + 코드 대조 시험이 더 단순하다.

## 결과
얻는 것: deploy가 이 영역의 라우트를 영역 이미지 라벨에서 읽는다. 감수하는 것: 라우트를 더할 때 `deploy-exposure.json`도 고쳐야 한다(시험이 잡는다). timeouts 값은 deploy가 가진 값이라 이 영역은 측정하지 않았다.

## 되돌리는 조건
계약 `Exposure` 형식이 바뀌면 따른다.
