# ADR-0028: LoRA-A 출력의 의미 규칙은 서버가 보증하고 서비스는 다시 검사하지 않는다 (turn-engine 코드 의존 제거)

## 상태
승인(헤드 결정 D104/ADR 0010, D109, 2026-10-29). ADR-0017의 2)번 결정(서비스가 turn-engine `validate_extraction`으로 의미를 검증)을 대체한다. 형식(1)과 값 타당성(3)은 ADR-0017 그대로다.

## 맥락
의미 규칙(save 규칙, targets, 문항 존재, next_item, 건너뛰기 순서)은 이전에 서비스가 turn-engine으로 검사했다. 구조 규칙 R7은 한 컴포넌트가 보증한 값을 다른 컴포넌트가 다시 검사하지 않는다고 정한다. 헤드는 이 규칙을 계약 데이터(`action_extraction_rules.json`)와 기준 검사기(`boundary_contracts.action_rules.check_action_extraction`)로 옮겼고, I9 extract 요청에 문항 순서표를 싣게 했다(`ExtractRequest{input, flow}`, boundary-contracts 2.2.1의 `HttpModelRuntime.extract(..., flow=)`).

## 결정
1) 원격 추론 호출은 `flow`(문진 스키마 `QuestionFlow`의 order·skips, 계약 QuestionFlowTable 모양)를 함께 보낸다. 서버는 규칙 위반 출력을 503 OUTPUT_INVALID로 낸다. 2) 서비스는 이 규칙들을 다시 검사하지 않는다. 계약 문장 그대로, 503 OUTPUT_INVALID는 같은 요청을 1회 다시 보내고 그래도면 NOT_COMMITTED다. 3) 서비스 고유 검사 4가지는 유지한다: 저장할 칸이 문항 세트에 있는가(UNKNOWN_SLOT), 현재 문항 밖 칸 저장(OUT_OF_CURRENT_ITEM), 값 형식·크기(VALUE_INVALID), 슬롯 정의·저장된 값과 종류(VALUE_TYPE_MISMATCH). 위반 때의 같은 요청 재호출 1회(D75)도 유지한다. 4) turn-engine에 코드 의존이 없다(requirements, 이미지, `flow.py`의 자체 표). `turn_engine_version`은 릴리스 매니페스트가 필수로 싣는 값이라 비교는 남기되 기준값을 라이브러리 설치본이 아니라 설정 `SURVEY_TURN_ENGINE_VERSION`(기본 0.4.3, 헤드 기준)에서 받는다. 이미지 라벨 `io.openit.turn-engine`은 `n/a`다.

## 왜 (따른 표준과 근거)
근거 출처: 구조 규칙 R7과 ADR 0010(헤드), boundary-contracts HTTP.md I9, CHANGELOG 2.2.0. 서버만 아는 모델 출력을 서버가 고치거나 거부하는 편이 한 곳에서 규칙을 바꿀 수 있다(규칙 명세 하나). (3)의 4가지는 규칙 명세가 문항 세트(칸 목록, 선택지, 단위)를 입력으로 받지 않아 서버가 보증할 수 없다. 그래서 서비스에 남기고 명세로 옮길지는 헤드가 정한다(OPEN_GAPS). 기본값 0.4.3은 헤드 기준값이며 측정한 값이 아니다.

## 검토한 대안과 버리는 이유
서비스가 계속 이중 검사: R7 위반이고 규칙이 두 곳에서 어긋날 수 있다(서버 규칙이 바뀌면 서비스가 모른다). 기준 검사기를 서비스가 직접 부르기: 같은 이유로 이중이다. (3)도 함께 지우기: 서버가 아직 보증하지 못해 틀린 값이 저장될 수 있다(U07, TE-1). `turn_engine_version` 비교를 없애기: 게이트가 승인한 동작과 서비스 동작이 어긋나는 것을 막는 D45/CR-005의 장치가 사라진다.

## 결과
얻는 것: turn-engine 의존 제거, 규칙의 단일 출처. 감수하는 것: 서버가 0.8.x이면 flow를 받아도 규칙 보증이 없다(서버를 먼저 model-runtime 0.9.0으로 올려야 한다). 프로세스 안 가짜 백엔드(`LocalModelSession`)는 flow를 받지 않아 규칙 보증이 없고, 이는 개발·시험용이다. `turn_engine_version` 기준값이 배포와 어긋나면 적재가 거부되므로 deploy가 값을 책임진다.

## 되돌리는 조건
서버가 규칙을 보증하지 못하는 것이 확인되면(재현 사례) 해당 규칙만 서비스 검사로 되돌린다. (3)이 규칙 명세로 옮겨지면 서비스 쪽 검사를 지운다.
