# ADR-0022: 정지 사유 pause_reason은 알림 행과 세션 문서에서 도출한다 (CR-H002)

## 상태
승인(헤드가 계약 2.1.0으로 채택).

## 맥락
위험 신호 정지와 되묻기 한도 정지(ADR-0020)가 둘 다 `PAUSED_RISK`이고 모양이 같아 직원 콘솔·지표가 구분하지 못했다. 계약 PUBLIC_API H절이 optional `pause_reason`(`RISK|REASK_LIMIT|OTHER`)을 `SessionState`, `StaffAlert`, `StaffSessionView`, `TurnFailureSignal`에 더한다. 뒤의 둘은 이 영역의 문진 스키마(`schema/schemas`)라 우리가 고친다.

## 결정
- 문진 스키마: `TurnFailureSignal`(여섯 파일의 같은 정의)에 optional `pause_reason`, `StaffSessionView`에 optional `pause_reason`(정지 중일 때)과 알림 항목의 optional 필드(pause_reason, delivery_attempts, last_delivery_status, manual_notice_*). 정수 스키마 버전 1 그대로(추가형).
- 값: 위험 매처 셋(발화 선별, 입력원, 슬롯 규칙)과 외부 위험 신호 severity RISK는 `RISK`, 되묻기 한도는 `REASK_LIMIT`, 외부 신호 severity CALL_STAFF(위험 판정이 아니라 호출)는 `OTHER`.
- 저장: 알림 행에 `pause_reason`. 세션 상태 조회는 세션 문서의 마지막 PAUSE 기록에 위험 사유가 있으면 `RISK`(문서가 정본), 없으면 그 정지를 낳은 최신 알림의 사유, 알림도 없으면 `OTHER`. 정지가 아니면 필드를 생략한다. 턴 신호는 알림이 있는 턴에서만 싣는다.
- `PAUSED_RISK` 이름은 그대로.

## 왜
- 세션 문서(`SessionStore` 스키마)의 `PauseEntry`에 새 종류를 넣으면 turn-engine·골든과 공유하는 문서 모양이 바뀐다. 추가 필드 하나를 알림 행에 두면 같은 효과를 영역 내부 변경으로 얻는다.
- 위험 정지의 정본은 세션 문서(`reasons`가 비어 있지 않음)라 알림 저장소가 죽어도 `RISK`는 맞게 나온다. 되묻기 한도와 외부 호출은 문서에 사유가 비어 있어 알림 행에서만 구분된다.
- 매처마다 표시를 달지 않고 `_pause_reason(st)` 한 곳에서 도출한다: 정지를 만드는 알림 종류가 RISK와 되묻기 한도뿐이어서 표시가 빠질 곳이 없다.
- 열거 확장 대비로 읽는 쪽이 모르는 값을 OTHER로 본다는 것이 계약 규약이다.

## 검토한 대안과 버리는 이유
- 세션 문서 `PauseEntry`에 사유 종류 추가: 위 이유로 버린다(문서 모양 변경의 파급).
- 상태를 `PAUSED_REASK_LIMIT`로 분리: 계약이 MAJOR 변경이라 버렸다(CR-H002 4절).
- 사유를 응답마다 로그 문장 파싱으로 추정: 문구 변경에 깨진다.

## 결과
얻는 것: 직원 콘솔·지표가 두 정지를 구분한다. 감수하는 것: (1) 알림 저장에 실패한 되묻기 한도 정지는 상태 조회에서 `OTHER`로 나온다(미상). (2) 이 기능 이전에 만들어진 알림은 사유가 없어 되묻기 한도 정지가 `OTHER`로 보인다. (3) 턴 신호의 사유는 알림이 있는 턴에만 실린다.

## 되돌리는 조건
세션 문서에 정지 사유를 넣는 스키마 v2가 생기면 도출 순서를 문서 우선으로 줄이고 이 ADR을 대체한다.
