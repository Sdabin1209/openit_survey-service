# ADR-0016: 키오스크 토큰은 기기별로 받고 세션은 만든 기기만 접근한다

## 상태
일부 대체: 인증 방식은 ADR-0031(gateway mTLS와 X-Openit-Device)이 대체한다. 세션 소유 확인과 기기 토큰 표는 2.x 호환으로 남는다.
승인(D88 U8)

## 맥락
하나의 공유 키오스크 토큰으로는 한 기기의 유출이 모든 세션 접근으로 번지고, 누가 어느 세션을 만들었는지 알 수 없다(감사 B2).

## 결정
`SURVEY_KIOSK_DEVICE_TOKENS`(NAME_FILE 우선) 표 `device_id=토큰`(16자 이상). 세션 시작 때 만든 기기를 알림 DB의 `session_meta.device_id`에 기록하고, 이후 turns/end/state는 같은 기기 토큰만 허용한다(다른 기기·공유 토큰은 404). 공유 토큰은 하위 호환으로 동작하되 `/readyz`의 `kiosk_tokens.shared_kiosk_token=true`로 경고한다. 세션 ID를 알아도 토큰이 다르면 접근할 수 없다.

## 왜 (따른 표준과 근거)
표준: 클라이언트별 자격 증명과 객체 수준 인가(소유자 확인, OWASP API1). 근거 출처: DECISIONS.md D88 U8.

## 검토한 대안과 버리는 이유
공유 토큰 유지: 위험이 그대로. 세션 ID를 추측 불가 값으로만 만들기: 생성 규칙은 프론트 소관이고 소유 확인을 대신하지 못한다.

## 결과
얻는 것: 기기 단위 폐기·추적, 세션 소유 확인. 감수하는 것: 기기 토큰 배포·회전 절차 필요(재시작해야 적용), 구성이 기기 토큰이면 알림 DB를 읽어 소유를 확인하므로 알림 DB 장애가 키오스크 경로에 영향을 준다.

## 되돌리는 조건
토큰 회전을 서비스 재시작 없이 하려면 토큰 표를 주기적으로 다시 읽도록 바꾼다.
