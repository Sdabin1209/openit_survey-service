# ADR-0066: 서버가 발급하는 세션 ID는 secrets.token_hex(32)

## 상태
승인(헤드 결정 2026-11-08, codex 검토 통과). ADR-0065의 서버 발급 세션 ID를 구체화한다(발급 방식만 바꾼다).

## 맥락
세션 ID를 `secrets.token_urlsafe(32)`(43자, 문자 `A-Za-z0-9-_`)로 발급했다. 계약 `Id`(`[A-Za-z0-9][A-Za-z0-9._:-]*`)는 첫 글자가 `_`·`-`이면 어긴다(확률 2/64). 그런 ID는 (1) Trace 봉투에서 `x-`+SHA-256 앞 32자로 변환되고(CONVENTIONS 116행) 수집 쪽(ops-feedback)이 봉투와 trace의 session_id가 다르다며 거부했다(데모 DEAD 7건, 2세션 모두 첫 글자 `_`). (2) `ResultReadyEvent.session_id`(`Id`)에는 원본이 그대로 실려 형식을 어긴다.

## 결정
`secrets.token_hex(32)`로 발급한다: 64자 소문자 16진.

## 왜
- 공개 `SessionId`(`^[A-Za-z0-9_-]{1,64}$`)와 계약 `Id`를 동시에 만족하는 문자 집합이라 어느 경계에서도 변환이 필요 없다(CONVENTIONS 116행 끝: 발급 쪽이 `Id`로 발급하면 변환은 쓰이지 않는다).
- 엔트로피는 32바이트(256비트)로 그대로다(OWASP 세션 관리: 예측 불가). 길이 64는 공개 상한과 같다.
- 표준 라이브러리 `secrets`(CSPRNG)를 그대로 쓴다.

## 검토한 대안과 버리는 이유
- token_urlsafe 유지, 수집 쪽만 고치기: 수집 쪽은 계약대로 고치는 중이지만 `ResultReadyEvent`의 `Id` 위반은 남는다.
- token_urlsafe 뒤 첫 글자 재추첨: 분포가 한쪽으로 치우치고 코드가 늘어난다.
- UUID4: 엔트로피가 122비트로 줄고 하이픈 형식이다.

## 결과
- 얻는 것: 변환 없는 Trace 봉투, `ResultReadyEvent` 형식 준수.
- 감수하는 것: ID가 43자에서 64자로 길어진다. 이미 발급된 `_`·`-` 시작 세션은 그대로 남는다(데모는 새 DB로 시작).

## 되돌리는 조건
공개 `SessionId`나 `Id` 형식이 바뀌어 16진이 맞지 않게 될 때.
