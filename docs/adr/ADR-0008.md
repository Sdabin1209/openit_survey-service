# ADR-0008: 서버 턴 마감 6초와 timeout 체인

## 상태
승인(FAULT_POLICY 원칙 3), 값은 측정으로 조정(2026-10-28)

## 맥락
키오스크는 10초 안에 응답을 기다리고, gateway는 연결 1초 + 응답 헤더 8.5초에서 끊는다. 서버는 그 안에 확정하거나 NOT_COMMITTED로 끝나야 환자가 직원을 부르기 전에 재시도할 시간이 남는다.

## 결정
`SURVEY_TURN_DEADLINE_SECONDS` 기본 6초. 요청을 받은 때부터(API 사전 확인 포함) 세션 락 대기, 멱등 확인, 모델 호출 재시도, DB 대기, 확정 전체에 건다. 넘으면 NOT_COMMITTED로 응답하고 늦게 끝난 작업이 확정하지 못하게 취소 표시를 한다. 불변식: 키오스크 대기 10초 > gateway 9.5초 > 서버 마감 6초 + 응답 전달 여유.

## 왜 (따른 표준과 근거)
표준: 호출별 timeout의 합이 아니라 요청 전체에 거는 마감(deadline propagation)과, 바깥쪽 timeout이 안쪽보다 길어야 한다는 timeout 순서 원칙. 근거(측정, 이 PC, 로컬 PostgreSQL 컨테이너): DB 장애 때 턴이 `docker pause`에서 5.0초, 중지에서 2.0초에 끝났다(boundary.md §5). 그래서 6초면 사전 확인이 실패해도 마감 안에 든다. **측정하지 않은 것**: 실제 LLM 지연과의 조합, 현장 흐름에 맞는 값(FAULT_POLICY의 사용자 결정 항목, D88 U10은 6초를 임시값으로 유지).

## 검토한 대안과 버리는 이유
8초(이전 기본): gateway 헤더 상한 8.5초와 0.5초 차이뿐이라 응답이 전달되지 못했다(E2E에서 504 8.5초 관찰). 호출별 timeout 합산: 재시도가 겹치면 합이 마감을 넘는다.

## 결과
얻는 것: 환자 경로의 시간 상한과 재시도 여지. 감수하는 것: 진행 중인 모델 호출을 끊지 못한다(마감은 새 호출만 막는다), 느린 모델이면 정상 턴도 NOT_COMMITTED가 된다(재전송으로 복구).

## 되돌리는 조건
H1(24GB) 등에서 실제 모델 지연을 측정한 뒤 값을 재정한다(D88 U10), gateway·키오스크 timeout이 바뀔 때 불변식을 다시 맞춘다.
