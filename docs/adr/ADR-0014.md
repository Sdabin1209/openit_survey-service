# ADR-0014: 같은 질문 반복(REASK·CONFIRM) 상한은 기본 3, 문항 세트 저작값이 있으면 그 최솟값

## 상태
승인(D88 U10 잠정값)

## 맥락
되묻기가 끝없이 이어지면 환자가 문진을 마치지 못하고 직원도 모른다(감사 I1, G12).

## 결정
`SURVEY_MAX_CONSECUTIVE_REASK` 기본 3(끄려면 0을 명시). 연속 REASK·CONFIRM이 상한을 넘으면 직원 호출 경로(정지 + CALL_STAFF 알림)로 간다. 문항 세트의 `ask_limit`·`confirm_limit`·`unrecognized_streak_limit`가 있으면 가장 작은 값을 쓴다.

## 왜 (따른 표준과 근거)
근거 출처: DECISIONS.md D88 U10(3회 후 직원 호출, 임시값, H1 실측 뒤 재정). **근사**: 세 저작 값은 v1에서 서로 다른 연속 횟수였으나 v2에는 REASK·CONFIRM을 합친 연속 횟수만 있어 최솟값을 한 상한으로 쓴다(근거 기록 없음, 정확한 의미는 데이터셋·문항 저작 담당 확인 필요).

## 검토한 대안과 버리는 이유
끄기(이전 기본): 무한 되묻기. 값마다 따로 센 연속 횟수: 대화 로그에 필요한 정보가 없다.

## 결과
얻는 것: 되묻기 무한 반복 방지. 감수하는 것: 정상 대화가 길어지면 직원 호출이 늘 수 있다.

## 되돌리는 조건
H1 측정 뒤 값 재정, 문항 저작 담당이 세 값의 의미를 확정하면 별도 카운터로 분리.
