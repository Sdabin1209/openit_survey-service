# ADR-0019: 장애 시험은 자기가 띄운 PostgreSQL 컨테이너만 이름으로 멈춘다

## 상태
승인

## 맥락
DB 무응답 시험(`test_turn_ends_not_committed_within_deadline_when_db_is_frozen`)은 `docker pause`를 쓴다. 이전 구현은 라벨 `io.openit.dev-postgres=1`이 붙은 컨테이너를 찾아 `TEST_DATABASE_URL`의 포트와 맞는 것을 멈췄다. 같은 서버에서 다른 영역·세션이 같은 라벨의 컨테이너를 쓰므로 잘못 멈출 수 있었고, 포트 비교가 부분 문자열(`:5432`가 `:54321`에 맞음)이어서 더 넓게 맞을 수 있었다.

## 결정
시험이 일회용 PostgreSQL을 직접 띄운다(`tests/pg_container.py`). 이름에 실행마다 고유한 uuid를 넣고(`survey-service-test-<uuid>`), 그 이름으로만 pause/unpause/rm 한다. 호스트 포트는 Docker가 배정하고 127.0.0.1에만 연다. 이미지 `postgres:16`이 로컬에 없으면 pull하지 않고 SKIP한다. `test_pausing_own_container_leaves_other_containers_running`이 옛 라벨을 단 다른 컨테이너가 pause 뒤에도 running임을 확인한다.

## 왜
- 탐색(라벨·포트)은 남의 자원과 겹칠 수 있고, 생성한 쪽이 이름을 알면 탐색이 필요 없다. 자기가 만든 자원만 다루는 것이 가장 좁은 범위다.
- 고정 포트·고정 이름을 쓰지 않는다는 워크스페이스 규칙(여러 영역이 한 서버에서 동시에 시험)과 같은 방향이다.
- 인증은 trust(일회용, 127.0.0.1 한정, 비밀 없음). 이미지 주 버전 16은 운영(ADR-0002)과 맞춘다.

## 검토한 대안과 버리는 이유
- 라벨+포트 탐색 유지(포트 정확히 비교): 남이 같은 포트를 쓸 수는 없지만 TEST_DATABASE_URL이 가리키는 공유 컨테이너를 멈추는 것은 여전하다. 버린다.
- 실행별 라벨로 탐색: 이름을 아는데 탐색할 이유가 없다. 이름이 더 단순하다.
- 시험에서 pause 생략: 무응답 DB에서 턴 마감이 지켜지는지(ADR-0011)를 못 본다. 버린다.

## 결과
얻는 것: 다른 컨테이너에 영향 없음, TEST_DATABASE_URL 없이도 이 시험이 돈다. 감수하는 것: 시험 하나당 컨테이너 기동 수 초, docker와 로컬 `postgres:16` 이미지가 없으면 SKIP(통과로 세지 않는다). 기동 시간은 측정 안 함.

## 되돌리는 조건
docker 없이 무응답을 만드는 표준 수단(예: 전용 TCP 프록시 시험 도구)을 쓰게 되면 대체한다.
