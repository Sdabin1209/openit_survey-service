# ADR-0061: 공개 API 코드 단계 - SSE 수명·거름·상한, 신원 헤더는 게이트웨이 토큰만, 저장소 실패 503, 로그 큐

## 상태
승인(헤드 코드 단계 지시 2026-11-04, 계약 3.4.8: PUBLIC_API SSE, CONVENTIONS 6절, RUNTIME R2.4·R3.10·R3.20·R10.5, HTTP.md I9 호출자 규칙).

## 맥락
계약이 공개 API와 호출 규칙을 입출력 단위로 다시 정했다. 아래는 이 영역이 코드로 고른 것과 그 근거다.

## 결정
- **SSE 최대 수명**: `SURVEY_SSE_MAX_SECONDS`(계약 SurveyServiceEnv, 기본 300초, 시작값·측정 안 함). 스트림은 인증 만료 신호를 받지 못하므로(R2.4) 서버가 그 시각에 정상 종료하고 클라이언트가 새로 연결한다. deploy가 platform 세션 갱신 주기 이하의 값을 준다. 심박은 15초(`SURVEY_SSE_HEARTBEAT_SECONDS`).
- **SSE 이벤트 거름과 검증**: 연결의 `X-Openit-Roles`로 이벤트를 거른다(staff: alert·resolved, clinician: result_ready, 둘 다 있으면 둘 다, heartbeat·resync는 모두). 헤더가 없으면(직접 호출·옛 경로) staff 몫이다. `data:`는 이벤트별 계약 스키마(StaffAlert, ResultReadyEvent, HeartbeatEvent, ResyncEvent)로 내보내기 전에 검증한다(생산자 검증). 동시 연결 상한(`SURVEY_MAX_SSE_CONNECTIONS`) 초과는 429 `UNAVAILABLE` + `Retry-After`(전에는 503)다. 스트림 경로는 staff와 result-reader(clinician) 토큰이 모두 연다.
- **신원 헤더는 게이트웨이 토큰만**: `X-Openit-User`·`X-Openit-Roles`·`X-Openit-Device`는 `deploy-exposure.json`에 `upstream_token`으로 선언한 토큰(키오스크 공유 토큰 `survey-api-kiosk`, staff `survey-api-staff`, result-reader `survey-result-reader`)이 붙은 요청에서만 쓰고, 그 밖의 모든 토큰(기기 토큰·위험 신호 토큰·모르는 토큰)·토큰 없는 요청의 같은 이름 헤더는 라이브러리에 닿기 전에 지운다. 이전에 있던 "토큰 없이 `X-Openit-Device`만으로 키오스크 인증" 경로는 폐기했다(계약: 신원 헤더는 게이트웨이 토큰 요청에서만).
- **결과 `updated_after`**: 결과가 마지막으로 바뀐 시각 기준이므로 확인 표시(ack)가 세션의 `updated_at`·`update_seq`를 올린다(`touch`). 두 번째 확인은 처음 값을 지키므로 올리지 않는다.
- **저장소 실패**: 조회·세션 생성·쓰기 확정이 저장소 때문에 실패하면 턴과 개입 모두 503 `UNAVAILABLE`(+`Retry-After`, `details.reason=STORE_UNAVAILABLE`)이고 그 턴은 결과로 고정하지 않는다(R3.10). 턴 마감·모델 실패만 200 `NOT_COMMITTED`다(R3.20). 활성 릴리스가 없으면 `GET /v1/question-sets`와 `POST /v1/sessions`는 503 `NO_ACTIVE_RELEASE`다.
- **추론 호출자 규칙(I9)**: 404면 같은 턴 안에서 PUT 재적재 후 LOADED를 턴 마감까지 기다려 한 번 더 부른다(마감이 꺼진 구성은 그 호출의 시간 한도만큼). 읽기 시간 초과를 포함해 그 밖의 UNAVAILABLE은 남은 예산이 호출 상한 이상일 때만 다시 보낸다(전에는 시간 초과를 다시 보내지 않았다). OUTPUT_INVALID는 그래프가 같은 요청을 한 번 다시 보낸다.
- **로그**: 요청 스레드는 로그를 큐에 넣기만 하고 별도 스레드가 표준 출력에 쓴다. 출력이 막히거나 실패하면 줄을 버린다(R10.5: 요청을 실패시키거나 느리게 하지 않는다). 큐 크기 10000은 시작값이다.
- **시험용 문 제거**: 푸시 사설 주소 허용 스위치(`SURVEY_PUSH_ALLOW_PRIVATE_HOSTS` 읽기, `allow_private_hosts`, `push_allow_private`)를 지웠다. 시험은 `conftest.loopback_ok`로 127.0.0.1만 대체한다. 계약 SurveyServiceEnv에는 이 이름이 남아 있다(계약에서 지워 달라고 헤드에 보고).

## 왜
- 계약 조항이 정한 출력을 그대로 따른다. 값(300초, 10000)은 측정하지 않았다.
- 신원 헤더를 토큰으로 가르는 이유: 게이트웨이가 클라이언트의 같은 이름 헤더를 지우므로 이 헤더를 신뢰해도 되는 것은 게이트웨이가 붙인 요청뿐이다(OWASP ASVS 4.1.3 신뢰 경계).

## 검토한 대안과 버리는 이유
- 신원 헤더를 서비스 설정의 사용자→역할 표로 대신하기: 계약이 금지(자체 표 없음).
- 로그를 동기 쓰기로 두고 예외만 삼키기: 파이프가 가득 찬 막힘은 예외가 아니라 지연이라 요청을 막는다.

## 결과
얻는 것: 계약 조항과 코드가 같고 시험이 상태 코드·본문·헤더를 단언한다. 감수하는 것: 로그 줄이 출력이 오래 막히면 버려진다. 토큰 없는 키오스크 기기 경로가 사라져 배포가 키오스크 경로에 게이트웨이 토큰(`survey-api-kiosk`)을 붙여야 한다.

## 되돌리는 조건
계약이 SSE 수명·거름 규칙이나 신원 헤더 규칙을 바꿀 때.
