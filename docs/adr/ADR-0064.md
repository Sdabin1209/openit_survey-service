# 공개 HTTP 요청 DTO는 경계 계약을 참조한다

## 상태
채택.

## 맥락
공개 API 요청의 전체 모양은 영역 사이 계약인데 영역 내부 schemas/에 정의돼 있었다.
한계를 settings에서 다시 읽던 코드도 스키마 원본이 분리되면 잘못된 경로를 읽었다.

## 결정
공개 HTTP DTO는 boundary-contracts의 PublicApiRequests 정의를 정본으로 한다.
내부 스키마는 x-contract로 위임하고 생성 타입은 types/contract/에 둔다.
타입 생성 과정은 설치된 계약·소유자 패키지만 임시로 펼쳐 사용한다. 실행용 스키마 사본은 만들지 않는다.
SSE 생산자는 StaffStreamEvent를 검증해 이벤트 이름과 데이터의 대응도 계약에서 읽는다.

## 왜
구조 규칙 6과 스키마 배치 규칙을 따른다. 한계와 데이터 정의를 복사하지 않아 영역별 검토가 같은 원본에 근거한다.

## 검토한 대안
내부 DTO와 경계 DTO의 이중 정의는 수정 시 불일치를 만든다. 이웃 작업 폴더를 읽으면 독립 설치를 보장하지 못한다.

## 결과
생성 시 런타임 가상환경에 고정된 계약 패키지가 필요하다. 기존 내부 타입 모듈은 생성된 alias로 유지한다.

## 되돌리는 조건
계약 소유권·독립성·단일 원본이 보장되는 대체 생성 방식을 검증하면 새 ADR로 대체한다.
