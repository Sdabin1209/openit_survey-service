# ADR-0025: 근거 없는 값의 출처 분류 (점검 N-, 값은 바꾸지 않았다)

## 상태
기록(헤드 결정표 2026-10-29 '전 영역'). 값은 바꾸지 않았다. 아래 값은 **어느 것도 측정하지 않았다**(따로 적은 것 제외).

## 맥락
점검(docs/audit/standards-2026-10-29.md, N- 항목)이 근거 기록 없는 값을 찾았다. 값마다 출처를 분류해 남긴다. 분류: 측정(이 영역이 잰 값), 표준(이름 있는 표준이 정함), 제약(이웃 값·환경에서 도출), 관행(널리 쓰는 크기, 이름 있는 표준 아님), 임의(출처를 찾지 못함). 출처를 코드·문서에서 찾지 못하면 "임의"라고 적는다. 나중에 다른 출처가 밝혀지면 이 표를 갱신한다.

## 값과 출처
| 값 | 위치 | 분류 | 설명 |
|---|---|---|---|
| 소켓 읽기 15초, 접속 256, SSE 50 | settings.py `socket_timeout_seconds`, `max_connections`, `max_sse_connections` | 임의 | ADR-0018이 이미 "측정 안 함, 근거 기록 없음"으로 적음. 부하 측정은 이 상한 적용 전이고 이후 재측정 안 함 |
| 추론 호출 timeout 4초 (**ADR-0026이 환자 턴 호출에 대해 대체했다**) | `inference_timeout_seconds` | 제약(낡음) | 주석은 "프론트 10초 안에 두 호출"에서 도출. 서버 턴 마감이 6초가 된 뒤(ADR-0008) 갱신되지 않았다: 4초×2호출은 6초를 넘을 수 있고 턴 마감이 끊는다. 결정표 단계 B에서 호출별 예산 배분을 계약으로 정할 예정이므로 지금 바꾸지 않는다 |
| 추론 재시도 1회, 백오프 0.2초×회차(지터 없음) | `inference_retries`, remote.py `backoff` | 임의 | 타임아웃은 재시도하지 않는다는 규칙은 코드에 있으나(remote.py) 값의 출처는 못 찾았다 |
| 숫자 100만 이하, 문자열 200자 이하 | ADR-0017 `check_values` | 임의 | ADR-0017이 "거친 타당성 상한, 근거 기록 없음"으로 적음 |
| 요청 본문 64KB | api.py `MAX_BODY` | 임의 | 발화 1000자 상한(계약 값)과 문서 필드를 모두 담고도 훨씬 큰 값. 도출 기록 없음 |
| 유휴 만료 300초 | `session_idle_seconds` | 임의 | 출처를 코드·설계서에서 찾지 못함 |
| 상태 폴링 최소 간격 0.5초 | `state_poll_min_interval_seconds` | 임의 | 키오스크 폴링 빈도를 제한하는 값. 출처 못 찾음 |
| Retry-After 1초 | `retry_after_seconds` | 임의 | RFC 9110은 헤더 형식만 정한다. 값의 출처 못 찾음 |
| 푸시 구독 100, 푸시 접수 timeout 3초 | `max_push_subscriptions`, `push_timeout_seconds` | 임의 | 3초는 ADR-0021이 재알림 중 잠금 밖 대기의 상한으로 인용하나 값 자체의 도출은 없음 |
| 웹 푸시 TTL 3600초 | alerts.py `WebPushSender(ttl=3600)` | 임의 | RFC 8030의 TTL 헤더 값이다. 값의 출처는 못 찾음 |
| 릴리스 폴링 5초, 시작 대기 5초, 릴리스 재시도 5초→60초, 릴리스 보관 2개 | `release_poll_seconds`, `startup_wait_seconds`, `release_retry_*`, `keep_releases` | 임의 | 재시도 5→60초는 지수 백오프의 관행적 모양이나 값은 측정하지 않았다 |
| HTTP 클라이언트 timeout 10초 | `http_timeout_seconds` | 임의 | 이웃(릴리스 게이트, 수집) 호출용. 출처 못 찾음 |
| outbox 전송 주기 1초, 백오프 상한 60초(지터 없음), 완료 행 보관 24시간 | `export_*`, `outbox_keep_sent_hours` | 임의 | 단일 전송자라 지터의 효과가 작다. 값은 측정하지 않았다 |
| outbox 승격 유예 60초 | `outbox_stage_grace_seconds` | 제약(배수) | 턴 마감 6초(ADR-0008)의 10배. 배수 자체는 임의, ADR-0023 |
| SSE 이벤트 보존 1만 건 | service.py `trim_events(keep=10000)` | 임의 | "이어 받기 범위"라고만 설명. 이 범위를 정한 근거 없음 |
| 보존 정리 주기 3600초 | `retention_interval_seconds` | 임의 | 하루 단위 보존 기간(ADR-0015)에 비해 짧은 주기라는 것 외 근거 없음. 서비스 안 정리 스레드와 CLI를 둘 다 두는 이유도 기록 없음 |
| 세션 잠금 줄무늬 64개 | alerts.py(ADR-0021) | 임의 | 충돌 확률을 계산하지 않았다 |
| 직원 호출 보고 상한 20 | `staff_call_report_max_per_session` | 제약(규칙) | 재알림 상한 10의 2배(ADR-0021). 배수는 임의 |
| 위험 규칙의 부정 표지 간격 8자 등 문맥 상수 | risk_rules.py `_NEG_GAP_MAX` | 임의 | ADR-0013이 보인 측정은 적중 수 감소(20→4)이고 놓친 위험(미탐)은 측정하지 않았다 |
| 요청 ID 16자(uuid4 앞 16 hex = 64비트) | service.py | 관행 | 로그 상관용이라 충돌이 치명적이지 않다는 판단. 측정·표준 아님 |

## 왜 이렇게 기록하나
D89: 값을 고른 이유를 물으면 근거로 답할 수 있어야 한다. 근거가 없는 값은 없다고 적는 것이 첫 단계다. 값을 바꾸면 측정 없는 변경이 하나 더 생긴다.

## 결과
얻는 것: 근거 없는 값의 목록과 출처 분류, 어느 것도 측정하지 않았다는 사실. 감수하는 것: 값은 그대로다.

## 되돌리는 조건
측정(H1 부하·현장 흐름)이나 계약 값(단계 B)이 생기면 해당 행을 그 근거로 갱신하고 값을 바꾼다.
