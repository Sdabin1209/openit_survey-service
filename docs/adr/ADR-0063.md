# ADR-0063: survey-db 이미지 (영역 DB 컴포넌트, D126)

## 상태
승인(헤드 지시 2026-11-04, 계약 v3.4.11 AreaDatabaseEnv·DatabaseDeclaration, D126). ADR-0060(DB는 영역 컴포넌트)을 이미지로 구체화한다.

## 맥락
DB는 영역이 소유하는 컴포넌트다. 계정·권한·접속 규칙·TLS가 deploy의 손 작업이나 이웃 리포 구조에 기대면 영역이 자기 DB를 보장하지 못한다. 계약은 영역이 DB 이미지를 만들고 라벨 `io.openit.database`에 선언(DatabaseDeclaration)을 싣게 한다.

## 결정
- 기반은 `postgres:16`(공식 이미지). 선언 `db/database.json`: 엔진 postgresql, 주 버전 16, 포트 5432, 계정 `survey`(데이터베이스 `survey`, 권한 owner, `url_env` `SURVEY_DATABASE_URL_FILE`). 계정이 하나인 이유는 계약 SurveyServiceEnv에 DB 접속 변수가 하나뿐이기 때문이다.
- 빌드할 때 `db/gen_accounts.py`가 선언을 계약 스키마로 검증하고(계정 이름 중복, owner 없는 데이터베이스 거절) 탭 구분 표 `accounts.tsv`로 바꿔 이미지에 넣는다. 이미지 안에는 파이썬을 두지 않는다.
- 초기화는 공식 이미지의 initdb 훅(`/docker-entrypoint-initdb.d`)에서 한다(PostgreSQL 공식 이미지 표준). 계정은 `LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION`, 암호는 `DB_ACCOUNT_SECRETS_DIR/<계정>` 파일에서 읽는다(D84). owner는 자기 데이터베이스를 소유하고, dml 계정은 CONNECT·스키마 USAGE·표 SELECT/INSERT/UPDATE/DELETE·시퀀스 USAGE/SELECT를 owner가 앞으로 만드는 개체의 기본 권한(`ALTER DEFAULT PRIVILEGES`)으로 받는다. 데이터베이스(선언 DB와 기본 `postgres`)의 PUBLIC CONNECT를 회수한다. SQL은 psql 변수와 `format(%I/%L)`로 만들고 문자열을 이어 붙이지 않는다.
- `pg_hba.conf`는 `local all postgres peer`와 `hostssl ... scram-sha-256`만 둔다: 평문 접속 줄과 루프백 trust가 없다. `password_encryption=scram-sha-256`.
- TLS는 필수다: 진입점이 `DB_TLS_DIR`(기본 `/certs`)의 `tls.crt`·`tls.key`가 없으면 시작하지 않는다. 키는 postgres 소유 0600 사본으로 만들고(마운트 권한이 느슨해도 서버가 거절하지 않게), 60초마다 바뀐 것을 보면 다시 복사해 `pg_reload_conf()`한다(인증서 갱신). 최소 TLS 1.2.
- `max_connections=50`.
- Dockerfile `HEALTHCHECK`(`db/healthcheck.sh`): 선언 첫 계정의 암호 파일로 TLS(`sslmode=require`) 접속해 `pg_stat_ssl`에서 그 연결이 TLS인지 본다. 간격 10초, 제한 5초, 시작 유예 90초(initdb 시간), 3회 실패면 unhealthy. 값은 측정하지 않은 시작 값이다. `pg_isready`는 계정·암호·hostssl·TLS를 모르므로 쓰지 않는다. 인증서 이름 검증(verify-full)은 컨테이너 안에 루트가 없어 클라이언트가 한다.
- build-image.sh 변형 `db`: 요청된 계약 태그가 빌드 호스트에 설치된 boundary-contracts 버전과 같아야 한다(라벨이 사실이어야 하므로).

## 왜
- 공식 이미지 + initdb 훅: PostgreSQL 공식 이미지의 문서화된 확장 지점이라 업그레이드 때 동작이 유지된다.
- hostssl만: 계약이 TLS 필수를 요구한다(전 구간 HTTPS 방침). 평문 줄을 두지 않으면 클라이언트 설정 실수로 평문이 쓰이는 길이 없다.
- 선언을 빌드 때 표로 바꾼다: 이미지 실행 시 선언 파싱·검증 도구가 필요 없고, 선언과 이미지 내용이 같은 파일에서 나온다.
- `max_connections=50`: 측정하지 않은 시작 값이다. 서비스 풀 상한과 잡(백업·복구·정리)이 쓰는 연결의 합보다 넉넉한 어림이며, 측정으로 바꾼다.
- 인증서 60초 확인: 갱신 주기에 비해 충분히 짧은 어림이며 측정하지 않았다.

## 검토한 대안과 버리는 이유
- 초기화를 서비스 앱이 하기: 앱 계정에 CREATEROLE·슈퍼유저가 필요해진다.
- 초기화 스크립트 안에서 선언 JSON 파싱(파이썬 설치): 이미지가 커지고 공급망이 넓어진다.
- trust/평문 줄 허용: 계약 위반.
- dml 계정에 `GRANT ... ON ALL TABLES`: 초기화 시점에는 표가 없어 효과가 없는 코드가 된다(기본 권한만 쓴다).

## 결과
얻는 것: 영역이 계정·권한·접속 규칙·TLS를 이미지와 시험(실제 컨테이너에 verify-full 접속, dml DDL 거부, 평문·틀린 암호·trust 거절, 변이 4종 검출)으로 보장한다. 감수하는 것: 계정이 늘면 선언과 계약 SurveyServiceEnv를 함께 바꿔야 한다. 이번 선언의 dml 경로는 실제 서비스 선언에는 쓰이지 않고 시험 선언으로만 확인했다.

## 되돌리는 조건
계약이 DB 이미지를 deploy 소유로 되돌릴 때. `max_connections`는 측정 뒤 값을 바꿀 때.


## 2026-11-06 배포 권한 회귀 수정

기존 AreaDatabaseEnv의 DB_ACCOUNT_SECRETS_DIR에서 계정 비밀을 읽어 /run/survey-db-secrets(postgres 소유 0700, 파일 0600)에 준비한 뒤 공식 진입점으로 넘긴다. gosu가 보조 그룹을 재설정하므로 원본 배치 비밀 0640을 완화하지 않고 사용자 전환 뒤에도 읽게 하기 위함이다. 읽기 실패·빈 첫 줄은 초기화 전에 거부한다. DB 이미지 시험의 비밀 파일과 capability를 배포 조건에 맞췄다. 새 계약 입력은 없다.
