# ADR-0037: 이미지는 영역 빌드 진입점 build-image.sh가 계약 요청으로 만든다 (U42)

## 상태
승인(헤드 결정 U42, 계약 boundary-contracts 2.5.0, 구조 규칙 1). deploy가 이 영역의 Dockerfile 인자 이름과 산출 파일(VERSIONS.env)을 직접 알던 것을 대체한다.

## 맥락
deploy `build-images.sh`가 이 영역의 빌드 인자(COMMIT, BOUNDARY_TAG, ...)와 `build_wheels.sh`가 내는 `build/wheels/VERSIONS.env`를 직접 알았다. 영역은 서로의 구조를 모른다는 규칙 1 위반이다(U23 감사).

## 결정
1) 진입점은 `bash scripts/build-image.sh <요청 JSON 파일>`(리포 루트). 요청은 계약 `BuildImageRequest`로 검증한다(영역 경계 입력). 이 영역이 쓰는 키(`versions.boundary`, `versions.model_runtime`, `dependency_sources.boundary`, `dependency_sources.model_runtime`)가 없으면 실패한다. 기본 태그를 영역 안에 두지 않는다. `versions.survey_schema`는 쓰지 않는다(이 영역이 스키마의 소유자이고 라벨은 `schema/CONTRACT_VERSION` 정수). `turn_engine`은 받기만 한다. 모르는 `variant`는 실패한다.
2) 이웃 라이브러리는 요청의 `dependency_sources`(소스 트리)를 이름 있는 빌드 컨텍스트(`--build-context boundary_contracts=...`, `model_runtime=...`)로 Dockerfile에 주고, Dockerfile이 `pip install --no-deps`로 설치한다. 이웃 리포 경로나 빌드 중 SSH가 없다. 서드파티는 `requirements.lock`에서 PyPI로 설치한다(계약은 이웃 라이브러리의 네트워크 접근만 막는다). 이전 `build_wheels.sh`(원격 태그를 clone해 wheel을 만들고 VERSIONS.env를 냄)는 지웠다.
3) 결과는 표준 출력 마지막 줄 `BuildImageResult`(image, image_id, 이미지에 실제로 붙은 `io.openit.*` 라벨을 `docker image inspect`로 읽음). 진행 기록은 표준 오류. 라벨 값은 요청에서 온다(revision, boundary, model-runtime). 영역 자신의 값(survey-schema 정수, langgraph 버전)은 영역 소스에서 읽는다.
4) 환경 변수는 `DOCKER`(도커 실행 파일)와 `PYTHON`(boundary-contracts가 설치된 파이썬, 요청 검증용)뿐이다. 비밀 값은 받지도 이미지에 넣지도 않는다.

## 왜
계약 2.5.0 BuildImageRequest/Result의 정의를 그대로 따랐다. 요청 검증을 계약 validator로 하는 것은 R7의 반대편(영역 경계 입력은 받는 쪽이 검증)이다. wheel을 호스트에서 만들지 않고 Dockerfile 안에서 설치하는 이유: 호스트 가상환경(setuptools·wheel 설치 여부)에 의존하지 않고, 같은 요청이 같은 이미지를 낸다(멱등, 도커 캐시).

## 검토한 대안과 버리는 이유
호스트에서 `pip wheel`로 만든 wheel을 컨텍스트로 주기(이전 방식): 호스트 도구에 의존하고 빌드 산출 디렉터리(`build/`)가 영역 구조 노출이 된다. 이웃 소스를 `COPY`가 아니라 Dockerfile 안에서 `git clone`: 빌드 중 네트워크(SSH)를 쓰지 않는다는 계약 위반.

## 결과
얻는 것: deploy가 이 영역의 내부를 모른다. 감수하는 것: (1) 이름 있는 빌드 컨텍스트(`--build-context`)가 되는 도커 빌더(BuildKit/buildx)가 필요하다. (2) 이미지를 빌드할 때 서드파티 설치에 PyPI 접근이 필요하다(이전도 같았다). (3) 요청 검증용 파이썬에 boundary-contracts가 설치돼 있어야 한다. (4) `build_wheels.sh`를 부르는 옛 deploy는 깨진다 — deploy가 새 진입점으로 바꿔야 한다.

## 되돌리는 조건
계약의 진입점 형식이 바뀌면 따른다.
