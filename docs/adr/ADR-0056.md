# ADR-0056: 결과 전달 - 확인 표시(ack), result_ready 이벤트, 의사 역할 노출 (U83)

## 상태
승인(사용자 결정 2026-11-03, 계약 3.2.0 PUBLIC_API B절). 값(보존 365일)은 기존 접근 기록 설정을 그대로 쓴다.

## 맥락
문진 결과는 의사가 본다. 게이트웨이가 역할 `clinician`(사람 계정)에게 결과 읽기와 확인 표시를 열고, 상류에는 `result-reader` 토큰과 `X-Openit-User`를 붙인다.

## 결정
- `POST /v1/results/{session_id}/ack` 본문 `{}` -> 갱신된 `SessionResult`. 역할 `result-reader`, `X-Openit-User` 필수(없으면 401). 확인 계정·시각은 세션 메타(알림 DB의 `session_meta`)의 선택 열 `acknowledged_by`·`acknowledged_at`에 저장한다(마이그레이션 0007). `UPDATE ... WHERE acknowledged_at IS NULL`이라 두 번째 호출은 처음 값을 지킨다(멱등). 결과(`SessionResult`)에는 확인된 뒤에만 두 필드가 나온다.
- 문진 스키마 `SessionResult`에 선택 필드 두 개 추가(정수 버전 1 호환 추가, `schema/CHANGELOG.md`).
- 접근 기록: 결과 읽기에 더해 ack도 `staff_access_log`에 계정 ID와 결과 `ACK`로 남긴다. 못 남기면 아무것도 바꾸지 않고 503이다(기존 fail-closed). 보존은 `SURVEY_ACCESS_LOG_RETENTION_DAYS` 기본 365(ADR-0015).
- `result_ready`: 세션 종료(`ENDED_*`)를 쓰기 확정한 턴에서 직원 SSE 허브로 `{session_id, status, ended_at}`를 한 번 낸다. subject_ref 없음, 웹 푸시 없음. **저장하지 않는 실시간 이벤트**다(SSE `id:` 줄 없음, `Last-Event-ID`를 바꾸지 않는다).
- `deploy-exposure.json`: `/v1/results`, `/v1/results/*`(GET)와 `/v1/results/*/ack`(POST)를 account/clinician, 상류 토큰 `survey-result-reader`로 선언한다. 위험 신호·`/metrics`는 denied로 남는다.

## 왜
- ack를 세션 메타에 둔 이유: 환자 연결 정보와 같은 수명·보존(세션 보존 정리가 함께 지운다)이고, 세션 문서(모델이 보는 기록)를 바꾸지 않는다. 별도 표는 같은 키를 한 번 더 조회한다.
- 재저장 방지를 SQL 조건으로: 앱 쪽 읽고-쓰기는 동시 ack에서 두 번째 값이 이긴다. 한 문장이 원자적이다.
- `result_ready`를 저장하지 않은 이유: 이벤트 표(`alert_events`)는 알림(alert_n) 행에 묶여 있고 순번이 `Last-Event-ID` 재개의 기준이다. 결과 도착은 목록 API(`GET /v1/results`)로 언제든 다시 맞출 수 있는 파생 정보라, 알림 모델을 바꾸지 않는다.

## 검토한 대안과 버리는 이유
- result_ready도 `alert_events`에 저장: 알림이 아닌 행이 섞여 재개 의미(알림·해결 순번)와 `StaffAlert` 본문 계약이 깨진다.
- 웹 푸시: 계약이 결과는 화면에서 본다고 정했다.

## 결과
얻는 것: 의사 확인이 남고 도착이 즉시 보인다. 감수하는 것: SSE가 끊긴 사이 종료된 세션의 `result_ready`는 재전송되지 않는다(목록으로 맞춘다). ack는 세션이 끝나기 전에도 가능하다(부분 결과 확인; 계약이 막지 않았다).

## 되돌리는 조건
계약이 도착 알림을 재개 가능하게 요구하거나 ack 의미를 바꿀 때.
