# ADR-0001: 세션·outbox·알림 저장소의 개발·시험 기본으로 SQLite를 쓴다

## 상태
승인(D85 이전부터의 기본값)

## 맥락
서비스는 세션 문서, Trace outbox, 알림 DB를 영속해야 하고, 개발자와 시험은 별도 서버 없이 이 저장소를 써야 한다(영역 규약 D22: 개발은 컨테이너 밖, 이웃 없이 혼자 시험).

## 결정
`SURVEY_DATABASE_URL`이 없으면 SQLite 파일(`SURVEY_SESSION_DB`, `SURVEY_OUTBOX_DB`, `SURVEY_ALERT_DB`)을 쓴다. WAL 모드, `synchronous=FULL`. 같은 SQL 본문을 PostgreSQL 구현과 공유한다.

## 왜 (따른 표준과 근거)
**정정(2026-10-29, 표준성 점검 A01)**: 이 항목은 처음에 12-factor의 "개발/운영 동등성"을 따른다고 적었으나 사실과 반대였다. 12factor.net 10항 "Dev/prod parity"(https://12factor.net/dev-prod-parity)는 "예를 들어 로컬에서 SQLite, 운영에서 PostgreSQL"을 **피해야 할 예**로 들고, 개발자는 "개발과 운영에서 서로 다른 백킹 서비스를 쓰려는 유혹을 이겨내고" 같은 종류·같은 버전을 써야 한다고 한다(원문을 이 날 열람해 확인, 요약 도구를 거친 인용이라 문장 대조는 사람이 한 번 더 할 것). 따라서 SQLite 기본은 12-factor를 따르는 선택이 **아니다**. 이 결정은 표준에서 벗어난 선택이고 아래 근거로 감수한 것이다.
근거(제약): 영역 규약 D22(개발은 컨테이너 밖, 이웃 없이 혼자 시험)와 서버 설치 없는 로컬·CI 시험. 완화 수단: 같은 SQL 본문을 PostgreSQL 구현과 공유하고 `tests/test_store.py`가 메모리·SQLite·PostgreSQL에 같은 적합성 시험을 건다. 12-factor가 경계하는 위험(두 백킹 서비스의 동작 차이)이 남으므로 PostgreSQL 쪽 시험(TEST_DATABASE_URL)을 따로 돌린다. 근거 출처: docs/design.md §6의 [결정].

## 검토한 대안과 버리는 이유
메모리 구현만: 재시작 시 세션 유실이라 영속 시험이 안 된다(메모리 구현은 따로 시험용으로 둔다). 처음부터 PostgreSQL만: 로컬·CI에 서버가 필요하고 영역 혼자 시험 규칙(D22)과 맞지 않는다.

## 결과
얻는 것: 설치 없는 개발·시험, 같은 SQL의 이중 검증. 감수하는 것: 단일 프로세스 쓰기(동시 쓰기 한계), 서버 간 공유 불가, 운영에서는 쓰지 않는다(ADR-0002).

## 되돌리는 조건
운영을 단일 노드 SQLite로 하기로 결정이 바뀌거나, 시험 속도·재현이 PostgreSQL 컨테이너로 충분히 좋아져 두 방언을 유지하는 비용이 이점을 넘을 때.
