# ADR-0049: 시간 상한 사슬 extract 3.0 / respond 5.0 / 턴 마감 9.0 (ADR-0008, ADR-0026의 값을 대체)

## 상태
승인(사용자 결정 2026-10-30, 헤드 지시). Supersedes: ADR-0008의 턴 마감 6초와 ADR-0026의 respond 2.0초(구조와 재시도 규칙은 그대로 유효).

## 맥락
GPU 실측 전이라 응답 생성(respond)이 2.0초 안에 끝나지 않을 수 있다. 호출별 상한의 합 + 여유가 턴 마감이고, 그 바깥에 gateway와 키오스크의 대기가 있다.

## 결정
extract 3.0초(그대로), respond 5.0초(2.0 -> 5.0), 서버 턴 총 마감 9.0초(6.0 -> 9.0: 두 호출 합 8.0 + 여유 1.0), gateway 10.5초, 키오스크 12초. `Settings` 기본값과 `link_inference.RemoteInference` 기본 인자를 바꿨다.

## 왜
- 출처: 사용자 결정과 계약 CONVENTIONS의 시간 상한 사슬(바깥 대기 > 안쪽 마감 > 호출 상한의 합 + 여유). **측정하지 않았다**(GPU 실측 전의 잠정값).
- 재시도 규칙(남은 예산 >= 호출 상한일 때만)은 새 값에서도 맞다: extract가 비타임아웃 오류로 일찍 실패하면 남은 예산이 9.0에 가까워 extract(3.0)·respond(5.0) 모두 재시도할 수 있고, 두 호출이 상한까지 쓰면(8.0) 남는 1.0 < 3.0이라 재시도하지 않는다.

## 검토한 대안과 버리는 이유
- respond만 5.0으로 올리고 턴 마감을 6.0으로 두기: 합 8.0이 마감을 넘어 정상 턴이 NOT_COMMITTED가 된다.

## 결과
얻는 것: 느린 응답 생성도 한 턴 안에 끝난다. 감수하는 것: 장애 때 환자가 기다리는 최대 시간이 6초에서 9초로 는다(DB 장애 시험의 상한도 같이 바뀌었다).

## 되돌리는 조건
GPU 실측으로 respond가 2초 안에 끝나는 것이 확인되면 값을 다시 정한다.
