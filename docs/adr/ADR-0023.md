# ADR-0023: Trace outbox 행을 세션 commit과 같은 DB 트랜잭션에 쓴다 (H02)

Supersedes: [ADR-0009](ADR-0009.md)의 '결정' 중 "턴 처리는 outbox에 로컬 INSERT 한 번만 한다"(전송·재시도·DEAD·상한 부분은 그대로 유효)

## 상태
승인(헤드 결정표 2026-10-29 단계 A, H02). 표준 이름과 요구 내용은 기억에 근거하며 원문(microservices.io)은 이 세션에서 열람하지 않았다.

## 맥락
점검(docs/audit/standards-2026-10-29.md H02)이 찾았다: ADR-0009는 "트랜잭션 outbox 패턴"이라 불렀으나 구현은 세션 commit이 끝난 뒤 별도 호출로 outbox에 넣었고(실패는 삼킴), SQLite에서는 파일도 달랐다. 세션 변경이 영속인데 프로세스가 죽으면 그 턴의 Trace가 없다. 재현 시험(`tests/test_outbox_atomicity.py`)이 commit 직후 사망을 주입해 이를 보였다(수정 전 실패).

## 결정
- outbox 표를 세션과 같은 DB에 둔다. PostgreSQL은 원래 한 데이터베이스였고, SQLite는 outbox를 세션 DB 파일에 연다(`SURVEY_OUTBOX_DB`는 더 쓰지 않는다. 그 파일에 남은 미전송 행은 옮기지 않는다. 운영은 PostgreSQL이고 SQLite는 개발·시험이다).
- 세션 commit 트랜잭션이 **예약 행**을 함께 쓴다(`store.commit(..., trace_envelope=...)`). 예약 행은 그때까지의 Trace를 담고 `next_attempt_at=STAGED_AT(1e18)`이라 전송 대상이 아니다.
- 턴이 끝나면 `store.finalize_turn`이 멱등 결과(`turns.result_json`)와 **완성된 Trace**(예약 행을 갱신, 전송 대상으로)를 한 트랜잭션으로 쓴다. commit이 없던 턴(NOT_COMMITTED 등)은 이때 새로 넣는다.
- 턴이 완성되기 전에 프로세스가 죽어 예약 행이 남으면 exporter가 유예(`SURVEY_OUTBOX_STAGE_GRACE_SECONDS`, 기본 60초) 뒤 전송 대상으로 승격한다. 내용은 사망 전까지의 부분 Trace라서 스키마 검증에 걸리면 `LOCAL_INVALID`로 DEAD가 되어 `/readyz`에서 보인다. 조용히 사라지지 않는다.
- 같은 DB 모드는 저장소의 `outbox_gate`가 sink의 outbox와 같은 객체일 때만 켜진다(`db.open_stores`가 연결). 그 밖의 조합(메모리 저장소, 다른 파일)은 이전 경로(`submit`)로 동작한다.
- 상한(`SURVEY_OUTBOX_MAX_PENDING`)에 닿으면 예약·완성 행을 쓰지 않고 `dropped_full`로 센다. Trace 때문에 세션 commit이 실패하지 않는다(계약 I6).

## 왜 (표준과 근거)
표준: Transactional Outbox 패턴(microservices.io, Chris Richardson): 업무 변경과 메시지 행을 같은 로컬 트랜잭션에 쓰고 별도 릴레이가 읽어 보낸다. 그러면 업무 변경이 영속이면 메시지도 영속이다. 계약 I6: 최소 1회 전달, 수집 장애가 턴을 막지 않는다. 수신 쪽 멱등((세션, 턴) 유일)은 그대로다.
예약 행을 둔 이유: Trace는 응답 생성·전달이 끝나야 완성되지만 세션 commit은 그 앞이다. commit 트랜잭션에 쓸 수 있는 것은 그때까지의 Trace뿐이라, "확정된 턴마다 행이 있다"는 불변식을 지키려면 예약 후 완성이 필요하다.

## 검토한 대안과 버리는 이유
- 턴 끝(`finalize_turn`)에서만 한 트랜잭션: commit과 finalize 사이 크래시에서 여전히 유실된다. 재현 시험이 이 사이를 주입하므로 통과하지 못한다.
- CDC(예: Debezium)로 세션 변경에서 Trace 도출: 표준 도구이나 인프라가 늘고 Trace의 모델 입출력은 세션 변경에서 도출되지 않는다.
- 새 `STAGED` 상태(CHECK 제약 확장): 기존 DB의 제약을 바꾸는 마이그레이션이 필요하다(마이그레이션 도구 대체는 단계 C). 그래서 `next_attempt_at` 표식을 썼다. 의미를 겹쳐 쓰는 대가로 `counts()`와 `oldest_pending_age`가 예약 행을 따로 다룬다.

## 결과
얻는 것: 세션 commit이 영속이면 그 턴의 outbox 행도 영속이다(크래시 창 없음). 시험이 SQLite에서 확인했다(PostgreSQL 변형은 TEST_DATABASE_URL이 있을 때 돈다).
감수하는 것: (1) 크래시로 남은 행의 Trace는 부분 내용이라 DEAD가 될 수 있다(유실이 아니라 보이는 격리). (2) 승격 유예 60초는 서버 턴 마감 6초(ADR-0008)의 10배로 정했고 **측정하지 않았다**. 마감을 넘겨 살아 있는 작업 스레드가 승격 뒤에 끝나면 완성본은 반영되지 않는다. (3) SQLite 개발 환경의 기존 `outbox.db`는 이어 쓰지 않는다. (4) 턴마다 쓰기가 한 번 늘고(예약) outbox 상한 확인 쿼리가 commit 트랜잭션 안에 들어간다(`COUNT ... LIMIT max_pending`, 비용 측정 안 함).

## 되돌리는 조건
Trace를 세션 변경에서 도출하는 구조가 되거나 CDC 도구가 운영에 들어오면 대체한다. 마이그레이션 도구가 들어오면(단계 C) 예약 표식을 정식 상태 열로 바꾼다.
