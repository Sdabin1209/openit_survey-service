# ADR-0047: 영역 구조 개편(D117): components / wiring / types / schemas

## 상태
승인(헤드 지시 U400, 2026-10-30). 대체하는 것: design.md 2절의 모듈 지도(모듈 이름이 바뀌었다). 와이어 형식·HTTP 응답·잡 출력은 바꾸지 않았다.

## 맥락
기존 코드는 모듈 사이 import가 얽혀 있었다(예: 저장소가 outbox 함수를, 로더가 필드 규격 검사를, API가 알림 서비스를 직접 import). 구조 규칙 6개(D104)와 head/docs/DESIGN.md가 요구하는 것은 컴포넌트마다 입력·출력 스키마 하나, 컴포넌트끼리 import 금지, HTTP는 `link_*`에서만이다.

## 결정
1. 업무를 위에서부터 나눠 컴포넌트 표를 `docs/components.md`에 두고(26개), 기존 코드는 빠진 규칙을 찾는 대조 자료로만 썼다.
2. 컴포넌트 사이의 연결(한 턴의 LangGraph 순서, 자원 주입, 조립)은 `wiring/`에 둔다.
3. 컴포넌트가 서로를 부르던 곳은 주입으로 바꿨다: 로더의 칸 규격 검사(`field_check`), 저장소의 outbox 쓰기(`outbox_gate.stage_in_txn/finish_in_txn`), API의 빈칸 계산(`orchestrator.blank_details`).
4. 같은 컴포넌트 안에 SQLite·PostgreSQL·메모리 구현을 한 파일로 둔다(`session_store.py`): PostgreSQL 구현이 SQLite 구현을 상속하고 메모리 구현이 같은 저장 효과 함수를 쓴다. 쪼개면 컴포넌트끼리 import가 생긴다.
5. 공용 기반 4개(`wiring/errors.py` `ports.py` `pg.py` `netguard.py`)는 컴포넌트가 import해도 되는 예외로 둔다(한계 L1). 3~10줄 보조 함수(`model_key`, `item_of`)는 복제한다(한계 L2).
6. `types/`는 `schemas/`에서 datamodel-code-generator(0.87.0, TypedDict)로 만들고, 같은 스키마 파일을 `types/_schemas/`에 사본으로 넣어 실행 때 `types.validate`가 쓴다(wheel·이미지에는 패키지 안의 파일만 들어간다). 사본도 생성물이라 재생성 비교(구조 검사 5번)가 어긋남을 잡는다.
7. 영역 사이 타입과 문진 스키마는 복사하지 않고 `x-contract`, `x-survey-schema` 주석으로 가리켜 검증기가 정본으로 위임한다.
8. 이웃 호출의 보내는 쪽은 `openit_link.clients`를 쓴다(D118). 받는 쪽은 `openit_link.App`으로 옮기지 못했다(CR-link-001).

## 왜
- 표준: functional core, imperative shell(Bernhardt)과 포트·어댑터(Cockburn), D117. 대안 비교는 아래.
- 측정하지 않았다: 구조 개편으로 지연이 달라졌는지는 측정하지 않았다(호출 경로는 같고 함수 호출이 늘지 않았다).

## 검토한 대안과 버리는 이유
- 컴포넌트마다 예외 클래스를 따로 두기: `except StoreError`가 갈라져 wiring이 컴포넌트별 예외를 모두 알아야 한다. 오늘 범위 밖이라 L1로 남겼다.
- 호환용 얇은 옛 모듈(shim)을 남기기: 구조 검사 6번에 어긋난다. 시험의 import를 고쳤다.
- 모든 입력을 호출마다 스키마 검증: 세션 문서 전체를 턴마다 여러 번 검증하게 된다. 측정하지 않았고, 오늘은 `TurnRequest`(턴 입구)만 바꿨다(L5).

## 결과
얻는 것: 컴포넌트 의존이 import로 드러나지 않고 구조 검사가 강제한다. 감수하는 것: 보조 함수 복제, 공용 기반 4개, 스키마 밖 조건 표(schemas/README.md)의 건수.

## 되돌리는 조건
복제한 보조 함수가 어긋나는 사고가 나거나 문진 스키마가 키 구조를 필드로 내면 복제를 없앤다(L2).
