# ADR-0002: 운영 저장소는 PostgreSQL(서비스별 DB·최소권한 계정)이다

## 상태
승인(D85 2단계, 2026-10-27 사용자 지시)

## 맥락
운영은 여러 요청이 동시에 세션을 쓰고, 백업·복구 도구와 계정별 권한 분리가 필요하며, 의료 문진 기록의 쓰기는 부분 반영이 없어야 한다.

## 결정
`SURVEY_DATABASE_URL`(`read_secret`, `_FILE` 우선)이 있으면 세션·outbox·알림이 모두 한 PostgreSQL 데이터베이스(deploy RUN.md 4-1-1의 `survey`)에 들어간다. 스키마는 시작 때 멱등 생성(advisory lock).

## 왜 (따른 표준과 근거)
표준: 운영 DB는 서버형 RDBMS, ACID 트랜잭션, 서비스당 전용 데이터베이스와 계정(최소권한), pg_dump 같은 표준 백업 도구. 근거 출처: 헤드 결정 D85(DECISIONS.md), deploy 문서(백업 도구 `pg-backup.sh`). 한 트랜잭션 쓰기 확정은 docs/design.md §6.

## 검토한 대안과 버리는 이유
계속 SQLite: 단일 프로세스·단일 파일이라 복제(프로세스 확장)와 서버 밖 백업이 어렵다. 관리형 클라우드 DB: 병원 온프레미스 단일 서버 전제와 맞지 않는다(근거 기록 없음, 구성은 deploy 소관).

## 결과
얻는 것: 동시 쓰기, 트랜잭션 격리, 표준 백업·복구, 복제 가능성. 감수하는 것: 별도 서버·계정 운영, 접속 장애가 서비스 장애로 번진다(ADR-0011로 상한을 둔다), 연결 문자열이라는 비밀 관리.

## 되돌리는 조건
저장 규모와 가용성 요구가 작아져 서버 운영 비용이 이점을 넘을 때, 또는 병원이 다른 RDBMS를 요구할 때(SQL을 두 방언이 공유하므로 전환 비용은 작다).
