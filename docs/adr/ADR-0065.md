# ADR-0065: 계약 4의 기기 인증과 서버 발급 세션 ID

## 상태
채택 (2026-11-08). Supersedes: [ADR-0016](ADR-0016.md)과 [ADR-0031](ADR-0031.md)의 기기 토큰·호환 인증 부분을 대체한다. 세션 소유 기기 확인은 유지한다.

## 맥락
계약 4는 공개 시작 본문의 session_id, 서비스의 기기별 토큰 표, 동적 module:function 환경 설정을 제거했다. 공개 HTTP 입력과 서버 발급 뒤 내부 메시지를 구분하고, 게이트웨이와 서비스 사이의 인증도 배포 선언에 남겨야 한다.

## 결정
공개 키오스크 인증은 게이트웨이의 mTLS가 담당한다. 서비스는 SURVEY_API_TOKEN_ENV가 가리키는 비밀을 검증하고, 그 요청의 X-Openit-Device로 세션 소유권을 확인한다. 비밀은 기본 SURVEY_API_TOKEN_FILE로 받으며 입력 선언에도 포함한다. 기기별 토큰 표와 호환 설정은 제거한다.

공개 시작 본문은 SessionStartBody로 검증하고 session_id를 거부한다. 서버는 CSPRNG로 ID를 발급해 내부 메시지와 Trace에 넣고 응답한다. SESSION_START는 멱등이 아니며 turn_id는 새 세션의 첫 턴 ID다. 내부 FrontendMessage의 session_id는 유지한다.

운영 의존은 계약의 HTTP 설정으로 연결한다. 시험 대역은 생성자로 주입하며 운영 진입점의 기본 배선과 구분한다. 알림 스트림은 staff와 clinician 계정 노출을 각각 선언하고, clinician은 survey-result-reader 상류 토큰을 쓴다. 이벤트 권한은 인증된 역할 헤더로 정한다. 구독 해지는 POST만 제공한다.

## 왜
계약 PUBLIC_API F절과 CONVENTIONS 6절의 신뢰 경계를 구현한다. 기기 인증은 TLS에서 끝내고, 서비스는 인증된 게이트웨이 요청과 세션 소유권을 확인한다. 서버 발급 ID는 프론트가 식별자를 선택하는 경로를 없애며, 선언된 HTTP 설정은 운영 배선의 검토와 독립 설치를 가능하게 한다.

## 검토한 대안과 버리는 이유
기기 토큰 호환 유지나 공개 시작 ID 수용은 계약 4와 어긋난다. 게이트웨이 서비스 토큰 없이 헤더만 신뢰하면 인증 근거가 사라진다. 내부 메시지의 ID까지 지우면 발급 후 오케스트레이터와 Trace 전달이 깨진다. 동적 모듈 설정으로 시험 대역을 넣으면 운영 계약에 구현 경로가 노출된다.

## 결과
배포는 기기 인증서·허용 목록과 별도로 같은 상류 토큰을 게이트웨이와 서비스에 연결해야 한다. 시작 재시도는 새 세션을 만들 수 있다. 기존 기기 토큰 설정은 거부되며, 운영 의존과 시험 대역의 배선이 분리된다. 문진 스키마 사본, 클라이언트 ID 거부, 서버 발급 ID·기기 소유권, 역할별 SSE와 실제 이미지·PG 재시작 스모크로 검증한다. 최종 버전과 시험 결과는 STATUS.md에 기록한다.

## 되돌리는 조건
계약 소유자가 인증·세션 ID·배선 규칙을 개정하고, 신뢰 경계와 독립성을 보존하는 대체 구현 및 배포 검증을 승인하면 새 ADR로 대체한다. 폐기된 설정을 임의로 복원하지 않는다.
