# ADR-0053: 위험 감지는 기본으로 끈다 (사용자 결정 L11)

## 상태
승인(사용자 결정 L11, 2026-11-03). ADR-0013의 기본값만 바꾼다(구조는 그대로 유효).

## 맥락
ADR-0013은 규칙 파일도 입력원도 없으면 임상 검토 전 임시 기본 목록을 켰다(`SURVEY_RISK_DEFAULT_RULES` 기본 on). 사용자가 위험 감지를 쓰지 않기로 했다(L11). 계약 3.2.0 `SurveyServiceEnv`의 `SURVEY_RISK_DEFAULT_RULES` 기본값도 `off`라 서비스 기본과 계약 기본이 어긋났다.

## 결정
`SURVEY_RISK_DEFAULT_RULES`의 코드 기본을 `off`로 바꾼다(`survey_service/settings.py`). 규칙 엔진(`prescreen`), 병원 규칙 파일(`SURVEY_RISK_RULES_FILE`), 외부 입력원 포트(`SURVEY_RISK_SOURCE`), 외부 위험 신호 API, 스키마는 그대로 둔다. 꺼진 채 시작했음을 숨기지 않으려고 `/readyz`에 `warnings: ["risk_detection_disabled"]`를 낸다(입력원이 없을 때만; 준비 조건은 아니다).

## 왜
- 사용자 결정(L11)이 근거다. 기본값을 코드에서 지우지 않고 설정으로만 끄므로 나중에 켜는 데 코드 변경이 없다.
- 계약 `SurveyServiceEnv` 기본(`off`)과 같아야 한다(U20과 같은 원칙: 계약 기본과 코드 기본의 일치, `tests/test_time_chain_vs_contract_u20.py`가 시간 값에 대해 같은 대조를 한다).
- 경고 코드: 조용히 꺼지면 운영자가 위험 감지가 없다는 사실을 놓친다. `/readyz`는 이미 운영 상태를 모으는 자리이고 경보 기준(boundary.md §5)에 쓰인다.

## 검토한 대안과 버리는 이유
- 규칙 엔진·포트 삭제: 사용자 결정은 "기본만 끔"이다. 삭제는 되돌리기 어렵다.
- `problems`에 넣어 503: 꺼짐은 장애가 아니라 선택이다. 준비 조건이 되면 서비스가 뜨지 않는다.
- 경고 없이 `staff_alert_source.active=false`만: 그 필드는 이미 있지만 경고 목록이 아니어서 경보 규칙이 읽기 불편하다(`warnings`는 이후 다른 경고도 담을 수 있다).

## 결과
얻는 것: 기본 구성에서 임상 검토 전 규칙의 거짓 알림이 없다. 감수하는 것: 기본 구성은 발화로 위험을 감지하지 않는다(환자 안전과 닿는 결정이고 사용자 몫이다). 문항 세트의 슬롯 `risk_rule`(IMMEDIATE)은 이 설정과 별개로 계속 적용된다(`_slot_risk`, ADR-0013). 시험의 기본 기대가 바뀌었다(`tests/test_alert_source_port.py`, `tests/test_service.py`, `tests/test_staff_view_and_rules.py`).

## 되돌리는 조건
사용자가 위험 감지를 쓰기로 하거나 병원 규칙 파일이 정해질 때(`SURVEY_RISK_RULES_FILE`).
