# ADR-0036: 결과에 빈칸의 원인 코드를 남긴다 (skipped_details, U35)

## 상태
승인(헤드 지시 OPEN_GAPS U35, 사용자 승인 2026-10-29). 문진 스키마 1.3.0(추가형).

## 맥락
`SessionResult.skipped`는 문항 ID 문자열 목록뿐이라 병원 시스템이 빈칸의 원인(환자가 모름, 거절, 불분명)을 알 수 없다. 이 형식은 병원 시스템이 읽으므로 호환을 지켜야 한다.

## 결정
1) 기존 `skipped`(문자열 목록)는 그대로 두고 새 필드 `skipped_details: [{item, slot?, reason}]`를 더한다(`schema/schemas/SessionResult.json`, 선택 속성, 서비스는 항상 낸다). `slot`은 칸의 모델 키(`answers[].key`와 같은 모양, 예 `Q7_1[soju].amount`)이고 칸을 알 수 없으면 생략한다. `skipped` 폐지는 2.0.0 후보다(CHANGELOG에 적음).
2) 원인 코드와 세션 사건의 대응(A 출력에서 옮길 뿐 서비스는 판단하지 않는다):

| 코드 | 세션 사건(LoRA-A 출력) | 근거: 학습 서버 현재 데이터(train+val+test 44,527행) |
|---|---|---|
| UNKNOWN(환자가 모름) | `values[].status = UNKNOWN`, action HOLD / reason UNCERTAIN | HOLD/UNCERTAIN 1324행이 모두 저장 안 된 값의 status가 UNKNOWN뿐 |
| REJECTED(거절·보류) | `status = REJECTED`, action SKIP / reason REFUSED 또는 REQUEST_SKIP | REFUSED 2077행, REQUEST_SKIP 2060행이 모두 REJECTED뿐 |
| UNCLEAR(불분명·범위 밖) | `status = UNCLEAR`, action REASK. reason: OUT_OF_RANGE 304, UNKNOWN_UNIT 148, VAGUE_QUANTITY 118, OTHER_BEVERAGE 82, RANGE_SPANS_OPTIONS 41, INVALID_OPTION 34, COUNT_EXCEEDS_DAYS 4, UNPARSED_VALUE 1 | 이 reason의 행(저장 안 된 값에 UNCLEAR가 있는 REASK)은 모두 UNCLEAR뿐 |
| (코드 없음) | `status = MISSING`(REASK / MISSING 등), `CONFLICT`(CONFIRM) | 아직 못 받았거나 확인 중이라 빈칸의 원인이 아니다. 올리지 않는다 |

값 규칙(`apply_value_rules`)이 범위 밖 값을 바꾼 출력(REASK/OUT_OF_RANGE, `value=null`, `UNCLEAR`)도 같은 UNCLEAR 행이다. 되묻기 상한에 닿아 직원이 호출된 경우(REASK_LIMIT)는 새 코드를 만들지 않고 마지막 status를 따른다(명세의 세 코드뿐).
3) 계산: 대화 로그를 순서대로 읽어 확정된(COMMITTED) 턴의 값마다 마지막 원인을 남기고, 나중에 값이 저장(`save=true`)된 칸은 뺀다(`survey_service/blanks.py`). 진행 기록의 건너뛴 문항 중 로그에서 칸을 찾지 못한 것은 문항만 적는다(UNCERTAIN은 UNKNOWN, REFUSED·REQUEST_SKIP은 REJECTED). 세션 문서의 모양은 바꾸지 않는다: 읽을 때 계산하므로 옛 세션에도 적용된다.
4) 환자 발화 원문은 넣지 않는다(감사 C2). 필드는 item, slot, reason 셋뿐이다(스키마 `additionalProperties: false`).

## 왜
데이터셋 labels가 정본이고(헤드 지시), 대응은 **학습 서버의 현재 데이터**에서 확인했다: `~/WS/dataset/data/final/lora_a_{train,val,test}.jsonl`(2026-10-29 02:26 생성, md5 앞 8자리 cc8242a5·cfd94af1·ddb66264) 44,527행에서 (action, reason, 저장 안 된 값의 status)를 셌다. 헤드가 먼저 센 값을 2026-10-30에 `ssh openit` 읽기 전용으로 다시 세어 같은 숫자를 얻었다(위 표). 이 ADR의 첫 판은 워크스페이스 사본 `reference/openit-server/data/final/lora_a_val.jsonl`(10/27 빌드, val 3221행)로 센 것이었는데, 사본은 서버의 현재 데이터와 다르고 `labels.py` md5가 같다는 것만으로는 데이터가 같다는 근거가 되지 않아 고쳤다. 사본으로 센 결론(status로 코드가 정해진다)은 현재 데이터에서도 같다.
추가형을 고른 이유: 병원 시스템이 읽는 형식이라 기존 필드를 바꾸면 깨진다(MAJOR). 정본 시각은 상태가 아닌 세션 사건(A 출력)이다.

## 검토한 대안과 버리는 이유
`skipped`를 객체 목록으로 바꾸기: 병원 시스템이 깨진다(2.0.0). 세션 문서에 칸별 원인을 새로 저장: 저장소 문서 모양 변경과 옛 세션 이행이 필요하다. 로그에서 계산하면 둘 다 필요 없다. 발화 원문을 근거로 붙이기: 최소 수집(C2) 위반.

## 결과
얻는 것: 병원이 빈칸의 원인을 코드로 안다. 감수하는 것: (1) 로그에서 계산하므로 대화 로그가 보존 기간으로 지워지면 같이 사라진다(세션 문서 전체가 지워진다). (2) 로그 항목이 많은 세션은 읽을 때 한 번 훑는다(턴 수에 비례, 측정 안 함). (3) 실제 모델이 데이터셋과 다른 status를 내면 그대로 옮긴다.

## 되돌리는 조건
`skipped`를 폐지하는 2.0.0에서 `skipped_details`가 유일한 필드가 된다.
