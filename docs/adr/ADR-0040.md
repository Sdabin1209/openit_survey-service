# ADR-0040: 문항 세트만 필요하면 I4 get_release_question_bank를 쓴다 (U47, SV-16)

## 상태
승인(헤드 지시 U47(5), 계약 boundary-contracts 2.7.0 I4 `get_release_question_bank`, release-gate 2e26816).

## 맥락
릴리스 로더가 문항 세트를 얻는 길이 `load_bundle`뿐이라 어댑터(수십~수백 MB)까지 내려받았다. 원격 추론 구성에서는 어댑터를 model-runtime 서버가 따로 받으므로 서비스가 받은 어댑터는 쓰이지 않았다(SV-16).

## 결정
로더(`ReleaseLoader._load`)는 추론 백엔드의 `needs_adapters`를 보고 고른다. 원격 추론(`RemoteInference`, `needs_adapters = False`)이면 계약 클라이언트 `get_release_question_bank(release_id)`로 문항 세트만 받고 어댑터 인자는 `{}`다. 서비스 안에서 모델을 올리는 백엔드(`InferenceServer`, 가짜 백엔드, `needs_adapters = True`)는 어댑터 파일이 필요해서 지금처럼 `load_bundle`을 쓴다. 메모리 구현(시험용 가짜 ReleaseReader)에도 같은 메서드를 더했다.
본문 해시(응답의 `content_hash`)는 클라이언트가 검증한다. 매니페스트와의 결속(`question_set.content_hash`, 버전, 필수 고정 문장)은 서비스의 `_check_bank`가 그대로 본다: 다른 것을 보는 검사라 중복이 아니다(R7).

## 왜
어댑터 다운로드는 원격 추론에서 쓰이지 않는 일이다. 게이트가 PASS가 아닌 릴리스에 412를 내는 것은 `load_bundle`과 같고, 서비스의 `_check_decision`도 그대로다.

## 검토한 대안과 버리는 이유
항상 문항 세트 호출만 쓰기: 서비스 안 가짜 백엔드가 어댑터를 필요로 한다(개발·시험 구성). 로더가 `SURVEY_INFERENCE_URL` 설정을 직접 보기: 설정이 아니라 백엔드 객체의 속성으로 정해야 구성 변경에 따라간다.

## 결과
얻는 것: 원격 추론 구성에서 릴리스 적재가 어댑터 용량만큼 줄어든다(측정 안 함). 감수하는 것: 번들이 어댑터를 매니페스트의 해시와 대조해 주던 검사를 이 구성의 서비스는 하지 않는다(어댑터를 쓰지 않으므로 의미가 없고, 받는 model-runtime이 자기 입력으로 검증한다). 어댑터가 실제로 필요한 곳으로 남은 것은 서비스 안 가짜 백엔드뿐이다.

## 되돌리는 조건
서비스가 어댑터를 직접 쓰는 구성이 생기면 `needs_adapters`를 그 백엔드에 건다.
