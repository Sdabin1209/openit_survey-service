# ADR-0038: 설정은 계약 SurveyServiceEnv로 검증하고 모르는 SURVEY_* 이름은 시작 때 거부한다 (U44)

## 상태
승인(헤드 지시 U44, 구조 규칙 4·5 / R7의 경계 입력 검증).

## 맥락
`settings.py`가 환경 변수를 손으로 읽었다(`env.get(이름, 기본값)`). 계약 `SurveyServiceEnv`(deploy가 컨테이너에 주는 환경 변수 집합)가 있어도 코드는 그것으로 검증하지 않았다. 오타 이름(`SURVEY_MAX_CONNECTION`)은 조용히 무시되어 기본값으로 돌았고, 형식이 틀린 값은 쓰는 자리에서야 터졌다.

## 결정
`Settings.from_env`가 먼저 `validate_env`로 환경을 계약 `SurveyServiceEnv` 스키마에 대조한다: (1) 필수 이름(`SURVEY_RELEASE_READER`, `SURVEY_TRACE_INGEST`, `SURVEY_MODEL_BACKEND`), (2) 값 형식(포트 숫자, 로그 수준, 비밀 파일은 절대 경로), (3) 계약 목록에 없는 `SURVEY_*` 이름 거부. 위반은 `ConfigError`(시작 종료 코드 2)이고 문구에는 **이름만** 있다(값은 비밀일 수 있다). `SURVEY_`로 시작하지 않는 이름은 본다(PATH 등). 값을 숫자·불리언으로 바꾸는 일은 손코드로 남긴다(스키마는 모두 문자열). 교차 규칙(`SURVEY_RISK_RULES_FILE`과 `SURVEY_RISK_SOURCE` 동시 불가, `_URL` 짝)도 스키마로 표현할 수 없어 그대로다.
(예외 목록 `_NOT_YET_IN_CONTRACT`와 `SURVEY_TURN_ENGINE_VERSION`은 계약 3.0.0 전환 때 없어졌다. ADR-0043.)

## 왜
영역 경계로 들어오는 입력(deploy가 주는 환경)은 받는 쪽이 계약으로 검증한다(구조 규칙 6: 영역 간 스키마는 헤드가 책임지고 영역은 그것을 따른다). 목록을 코드에 따로 복사하지 않는다: 계약 하나가 정본이다.

## 검토한 대안과 버리는 이유
알려진 이름 목록을 `settings.py`에 직접 두기: 복사본이라 계약과 어긋난다. 모르는 이름을 경고만 하기: 오타가 기본값으로 도는 것을 못 막는다(운영 사고).

## 결과
얻는 것: 오타·형식 오류가 시작 때 이름과 함께 드러난다. 감수하는 것: (1) **동작 변경**: 계약이 `SURVEY_MODEL_BACKEND`를 필수로 정하므로, 이전에 `SURVEY_INFERENCE_URL`만 주고 `SURVEY_MODEL_BACKEND`를 생략하던 구성은 이제 시작하지 못한다(시험 2개에 `SURVEY_MODEL_BACKEND=fake`를 더했다). (2) 계약에 새 이름이 생기기 전에 이 영역이 새 설정을 읽으면 시작이 거부된다 — 계약 변경 요청이 먼저다(시험 `test_every_survey_name_the_code_reads_is_accepted_by_the_contract_schema`가 어긋남을 잡는다). (3) 다른 영역이 같은 컨테이너에 준 SURVEY_* 이름도 거부된다.

## 되돌리는 조건
계약 목록과 코드가 계속 어긋나 배포를 막으면 경고로 낮춘다(헤드 결정).
