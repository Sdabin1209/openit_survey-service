## 11. 스키마 검증 범위

1. 요구사항 작성 형식, 중복 ID·YAML 키, 상황·계약·필드 참조가 유효한지 확인한다.
2. JSON Schema 2020-12 문법과 상대 참조, 필수 필드·중첩 타입·분기·필드 관계를 확인한다.
3. 필드별 의미·필요 이유·근거 요구사항 및 입력 필드의 원천 계약·시점을 확인한다.
4. 생성한 all.json·standalone·요구자료가 원본과 일치하는지 확인한다.
5. 요구자료에 선언한 정형 값이 담당 필드에 들어갈 수 있는지 확인한다. 정형 예시의 허용·거부와 경계별 예시 존재를 확인한다.
6. 케이스 정보의 필드 연결·완전한 예시·표기 보존과 고정 원천·목적 예시의 지정 필드 전달을 검사한다. 모든 단계의 연결이나 상태 전이를 검사하는 것은 아니다.
7. 업무 컴포넌트는 실행하지 않는다. 정답 코드 선택·응답 의미·질문 순서·저장 동작의 정확성을 판정하지 않는다.
8. 검증 수치와 적용 범위는 VERIFIED.md에 기록한다. 선언한 예시의 표현 가능성을 모든 요구의 완전성으로 일반화하지 않는다.
