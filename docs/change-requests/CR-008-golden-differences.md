# CR-008 골든 예시와 구현 출력의 차이 분류

- 대상: `tests/golden/` (226 케이스). 방법과 한계: `docs/design.md` 10절, `CR-002`. 재생성: `python -m pytest tests/test_golden.py` (근거 전체는 `tests/golden_known.json`).
- 정보. 헤드가 예시 작성자에게 넘겨 달라.

## 결과

처리한 턴 234, 비교한 쌍 1220 중 1215 일치, 5 불일치. (a) 구현 결함 0(대조 중에 찾은 결함은 고쳤다), (b) 규칙 해석 차이 0, (c) 예시 오류 5.

고친 (a): 프론트가 보낸 말이 처리되지 않은 턴(종료된 세션, 멈춘 세션)에 프론트로 갈 입력이 없었다. 골든은 `{response_text: null, turn_failure_signal: null}`을 둔다(A5, A6, G5). 같은 형태를 낸다. 개입 결정에는 프론트가 없어 내지 않는다(J4b).

## (c) 예시 자체의 오류

- C11/t1, G10/t1, N6/t1 — 최종 상태의 확인 대기 ID(Y, X, Z)가 같은 예시의 로그 항목 저장 결정·응답 지시의 ID(N1)와 다르다. turn-engine CR-009가 같은 종류(자리표시자)를 컴포넌트 입력 쪽에서 보고했다. 같은 예시 안에서 한쪽이 틀렸다.
- J3/t1 — 같은 턴의 로그 항목 `response_text`("바로 직원을 불렀습니다...")와 프론트가 받은 `response_text`("직원에게 알려드리겠습니다.")가 다르다. 로그와 프론트가 받은 문장은 같아야 한다.
- J8a/t1 — 세션 정보 생성이 실패한 턴인데 최종 상태가 있다(모든 슬롯 없음). 만들어지지 않은 세션에는 상태가 없다. "만들었다면 이런 상태"라는 표기라면 그렇게 표시해 달라.

## 해석한 것 (차이는 아니지만 알린다)

- 골든에는 `turn_id`가 없다. 시험이 케이스·턴 번호로 만든다.
- 직원 콘솔 입력(StaffConsoleInput)은 한 턴에 한 값으로 나온다. 구현은 알림을 응답 생성보다 먼저 전달하고(지연 없이), 실패 신호가 있으면 신호만 담아 한 번 더 전달한다. 골든의 StaffConsoleInput은 마지막 전달 내용과 같다(J3, J8g의 `staff_alert: null`).
