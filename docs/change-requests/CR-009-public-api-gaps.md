# CR-009 공개 API(PUBLIC_API.md) 문서의 부족한 점과 이 영역의 해석

- 상태: 확인 요청. 아래 해석으로 구현했다(`survey_service/api.py`, `tests/test_public_api.py`). 헤드/프론트가 다르게 정하면 한 곳을 바꾼다.

## 문서가 정하지 않아 해석한 것

1. **시작·종료에는 `turn_id`가 없다.** 멱등(재시도 안전)을 지키려고 서버가 고정 ID를 쓴다: 시작 `start`, 종료 `end`, 유휴 만료 `idle-expire`. 그래서 같은 session_id로 시작을 다시 보내면 처음 응답이 그대로 돌아온다(진행 중인 세션에서 첫 질문을 다시 듣는 용도로는 쓸 수 없다). 발화의 `turn_id`로 이 세 값은 예약이라 400이다. 대안: 시작/종료도 `turn_id`를 받는다.
2. **`turn_id` 형식**: 문서는 "고유 문자열"뿐이다. `[A-Za-z0-9][A-Za-z0-9._:-]{0,127}`(경계 계약의 `Id`)로 제한한다. 맞지 않으면 400.
3. **상태 코드**: 400 형식(필드 누락·모르는 필드·길이·경로와 본문의 세션 ID 불일치·빈 발화), 401 토큰 없음·틀림(`BoundaryError`의 PERMISSION_DENIED, 403은 쓰지 않는다. HTTP.md는 PERMISSION_DENIED를 403으로 정하는데 PUBLIC_API는 401/403이라 401을 골랐다), 404 모르는 세션(발화·종료. 발화로 세션을 암묵적으로 만들지 않는다), 409 끝난 세션에 발화, 또는 같은 `turn_id`에 다른 입력, 429 동시 처리 한도(`SURVEY_API_MAX_INFLIGHT`, 기본 32, `Retry-After: 1`), 503 활성 릴리스 없음·저장소 오류.
4. **"순서 어긋남(409)"의 범위**: 끝난 세션(ENDED_*)에 발화는 409. 이미 끝난 세션의 종료는 200(말할 것 없음, 결과 전달은 다시 하지 않는다). 위험으로 멈춘 세션(PAUSED_RISK)에 발화는 200이고 `{response_text: null, turn_failure_signal: null}`이다(규칙 G5: 멈춘 동안에는 직원 결정만 받는다. 프론트는 "잠시 기다려 주세요"를 직접 보인다).
5. **발화 길이 상한**: 문서에 없다. 1000자(`SURVEY_API_MAX_UTTERANCE_CHARS`). 빈 문자열·공백만은 400.
6. **세션 ID**: 문서(1~64자 영문·숫자·`-_`)대로 검증한다. 이 형식은 경계 계약의 `Id`에 들어가서 봉투 변환(`x-` 해시)이 쓰이지 않는다.
7. **유휴 만료**: 마지막 기록 후 `SURVEY_SESSION_IDLE_SECONDS`(기본 300, 0이면 끔) 지난 진행 중 세션은 사용자 이탈(SESSION_END, `ENDED_LEFT`)로 닫고 결과 전달을 부른다. 위험으로 멈춘 세션은 직원이 정하므로 만료하지 않는다. 만료 뒤 발화는 409.
8. **`GET /healthz`, `/readyz`** 는 인증이 없다(HTTP.md 9절과 같다). 공개 API 호출은 모두 Bearer 토큰이 필요하다.

## 문서에 없어 구현하지 않은 것

- **직원의 개입 결정(재개·종료)을 받는 경로**: PUBLIC_API는 프론트 호출 4개만 정한다. `InterventionDecision`이 서비스에 들어오는 경로(직원 콘솔 → 서비스)는 여전히 없다(CR-003 4항). 위험으로 멈춘 세션은 이 경로가 생기기 전에는 풀 수 없다. 운영 전에 필요하다.
- **상태 확인 동작**(O06의 4번째 동작)은 `/readyz`로 대신한다. 세션별 상태 조회는 없다.
- 프론트 전달 실패(`DELIVER_FRONT`)는 응답을 못 받은 쪽만 알 수 있어 서버는 만들지 않는다. 프론트가 같은 `turn_id`로 재시도한다.
- 토큰 발급·회전, 한 키오스크당 토큰 분리, TLS: 운영 배포 담당(문서에도 미정).
